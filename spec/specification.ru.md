# Спецификация языка Ixion: неизменяемые данные и алгебраические типы

Редакция: **проект следующей версии**, 18 октября 2026 года.

Это нормативный проект целевого языка, а не описание возможностей выпущенного
компилятора. Несовместимые изменения перечислены в разделе 16. Текущее состояние
реализации и порядок перехода описаны в [плане реализации](implementation-plan.ru.md).
Код в примерах следует целевой семантике; до завершения перехода он может
не компилироваться существующей реализацией.

## 1. Модель языка

Ixion — статически типизированный язык для JVM с неизменяемыми данными,
функциями первого класса и алгебраическими типами данных (ADT).

Основные положения:

- значение структуры, варианта, кортежа или списка неизменно после создания;
- обычная привязка объявляется через `const`, локальное переприсваивание — через `var`;
- произведения моделируются структурами и кортежами, закрытые суммы — `enum` с данными;
- `case` является выражением с рекурсивными шаблонами и статической проверкой полноты;
- обобщённые типы и функции работают без неявного перехода к `any`;
- отсутствие значения и ожидаемые ошибки представлены `Option[T]` и `Result[T, E]`.

Иммутабельность не означает чистоту функций: ввод-вывод, исключительные аварии
и вызовы внешних модулей остаются эффектами. Система эффектов, линейность,
владение и borrow checking не входят в эту редакцию.

«ДОЛЖЕН» задаёт обязательное требование, «НЕ ДОЛЖЕН» — запрет,
«МОЖЕТ» — разрешённый выбор реализации. Наблюдаемое поведение одинаково
для прямого JVM-бэкенда и генерации Java.

## 2. Лексика и соглашения

Идентификатор начинается с Unicode-буквы или `_`, продолжается буквами,
цифрами и `_`. Регистр значим. Одиночный `_` — шаблон пропуска, не имя привязки.
Комментарии: `//` до конца строки и невложенные `/* ... */`.

Ключевые слова:

```text
case for while if else return struct enum def type const var pub use
new lambda true false with never
```

`new` сохраняется зарезервированным, но не требуется для конструкторов.
`unit`, `void`, `any`, `bool`, `char`, `int`, `float`, `double`, `string` —
предопределённые имена типов; переопределять их нельзя.

Литералы: `42`, `3.14`, `3.14f`, `3.14d`, `1e3`, `true`, `false`,
`'x'`, `"text"`, `()` и списки `[1, 2]`. Целый литерал имеет тип `int`
(32 бита), дробный без суффикса и с `f` — `float` (IEEE 754 binary32),
с `d` — `double` (binary64). Знак — отдельный префиксный оператор.
`char` соответствует одной UTF-16 code unit; `string` — неизменяемой строке.
Escape-последовательности: `\n`, `\t`, `\r`, `\b`, `\f`, `\\`, `\'`, `\"`, `\0`.

Пробелы и переводы строк разделяют токены и не меняют значение программы.
Точка с запятой не требуется. Запятые обязательны между параметрами,
аргументами, элементами кортежей, списков, полями и вариантами в объявлениях.
Замыкающая запятая разрешена. Ветви `case` разделяются запятыми.
Оператор `return` всегда имеет выражение: пустой возврат пишется `return ()`.
Это устраняет зависимость разбора `return` от перевода строки.

## 3. Модули и области видимости

```ixion
use <std>
use <domain/model>

pub def main() {
    std::println("Hello, Ixion")
}
```

Программа — модуль из импортов, объявлений типов, функций и `const`.
Исполняемые операторы находятся в функциях. Верхнеуровневый `var` запрещён.
Инициализаторы модульных констант выполняются один раз в порядке объявлений
после зависимостей; циклы инициализации диагностируются. Взаимно рекурсивные
функции и типы разрешены и собираются до проверки тел.

`use <a/b>` импортирует модуль с квалификатором `b`; обращения к экспортируемым
значениям и типам имеют вид `b::name`, `b::Type`. Коллизия квалификаторов — ошибка.
Алиасы импорта в эту редакцию не входят.

`pub` разрешён только перед верхнеуровневыми `def`, `const`, `type`.
Экспорт структуры открывает её поля и конструктор, экспорт суммы — все варианты
и их данные. Скрытые варианты и расширение суммы другим модулем запрещены.
Экспортируемая сигнатура не может упоминать приватный номинальный тип.

Имена типов и значений разрешаются в отдельных пространствах; конструктор
структуры доступен как значение с именем типа. Повторное объявление в одной
области — ошибка. Вложенная область может затенять внешнее имя. Привязки
параметров, `for` и шаблонов неизменяемы.

## 4. Привязки и глубокая иммутабельность

```ixion
const origin = Point(0, 0)
const empty: string[] = []
var current: Point = origin
current = Point(1, 0)
```

Все привязки инициализируются при объявлении. Аннотация типа необязательна,
если тип выводится из инициализатора. `const` запрещает повторное присваивание,
но не требует вычисления на этапе компиляции. `var` допустим только внутри
функции или лямбды и разрешает замену значения целиком.

Иммутабельность транзитивна: поле структуры, данные варианта, компонент
кортежа и элемент списка не могут служить изменяемой ячейкой. Две привязки
могут разделять память без наблюдаемого изменения значений.

```ixion
const before = [1, 2]
const after = std::append(before, 3)
// before == [1, 2], after == [1, 2, 3]

var point = Point(1, 2)
point = point with { x = 10 }
// point.x = 10 — ошибка даже для var
// before[0] = 10 — ошибка
```

Операторы присваивания `=`, `+=`, `-=`, `*=`, `/=`, `%=` и постфиксные `++`, `--`
допустимы только для локального имени `var`, с проверкой типа результата.
Они являются операторами, не выражениями, и возвращаемого значения не имеют.
Составное присваивание вычисляет правую часть один раз; арифметические
постфиксные операции доступны только числовым `var`.

Лямбда захватывает свободные локальные привязки **по значению в момент создания**,
включая текущее значение `var`. Переприсваивание захваченного имени внутри
лямбды запрещено; внутри можно объявить собственный `var`.

```ixion
var count = 1
const read = lambda (): int { return count }
count = 2
// read() == 1
```

## 5. Типы и совместимость

### 5.1. Базовые типы

Базовые типы: `bool`, `char`, `int`, `float`, `double`, `string`, `unit`, `never`, `any`.
`unit` имеет единственное значение `()`. Отсутствие аннотации результата функции
означает `unit`; нормальное завершение такого тела возвращает `()`.
`void` — устаревающее написание `unit`, а не запрет на использование значения.
В JVM-дескрипторе результата `unit` может кодироваться `V`, в контейнерах — объектом.

`never` не имеет значений и совместим с любым ожидаемым типом. Это тип выражения,
которое не завершает вычисление нормально, например `std::panic(...)`.
`null` в исходном языке отсутствует; нулевые ссылки JVM не являются значениями Ixion.

`any` — верхний тип: любое значение можно расширить до `any`, но обратного
неявного преобразования нет. Доступ к полям и вызов `any` запрещены без уточнения
через типовой шаблон. Он не является escape hatch для обхода иммутабельности.

### 5.2. Тождество, преобразования и вывод

Структуры и суммы номинальны: идентичность определяется модулем, объявлением
и аргументами типа. Совпадение полей не делает два объявления одним типом.
Кортежи, списки, функции и анонимные объединения сравниваются структурно.
Прозрачный alias не создаёт новый тип.

Допустимы расширения `char -> int -> float -> double`; они не обещают сохранения
точности. Автоматического сужения нет. В числовой операции выбирается общий
числовой тип по этой цепочке. В остальных контекстах преобразование должно
соответствовать ожидаемому типу. `bool` не является числом.

Вывод локален и учитывает ожидаемый тип. `[]` и полиморфные варианты без данных
требуют контекста либо явных аргументов типа. `const xs = []` без контекста — ошибка;
компилятор не подставляет `any`.

При объединении результатов ветвей сначала используется ожидаемый тип.
Без него выбирается одинаковый тип, общий числовой тип либо нормализованное
объединение типов результатов. `never` не увеличивает это объединение.
Неявное расширение до `any` при неудаче вывода запрещено.

### 5.3. Обобщения

```ixion
type Box[T] = struct { value: T }
type Pair[A, B] = (A, B)

def identity[T](value: T): T {
    return value
}

const a = Box[int](42)
const b: Box[string] = Box("hello")
const c = identity[int](42)
```

Параметры объявляются после имени типа или функции. Применение — `Name[T, U]`.
Число аргументов должно совпадать с числом параметров; повторные имена запрещены.
Все пользовательские generic-типы и списки **инвариантны**: `Box[int]` не является
`Box[any]`. Расширение числа внутри готового контейнера не выполняется.
Функциональные типы также инвариантны в этой редакции.

Вывод параметров конструктора и функции решает ограничения аргументов
и ожидаемого результата; неоднозначные и нерешённые параметры — ошибка.
Тело generic-функции проверяется для произвольного допустимого `T`: операции
над `T` разрешены только если они корректны для каждого `T`. Например,
`identity` допустима, а `x + x` для неограниченного `T` — ошибка.
Обобщения первого ранга; неявного обобщения локальных привязок нет.

### 5.4. Функциональные типы

Тип функции: `(A, B) => R`; функция без аргументов: `() => R`.
Лямбды используют `lambda (name: Type, ...): R { ... }`.
Аннотацию параметра лямбды можно опустить только при однозначном ожидаемом
функциональном типе; параметр записывается в круглых скобках.
Результат можно опустить при контексте или для `unit`.
Ограничение текущих JVM-интерфейсов на четыре аргумента не является правилом языка.

## 6. Произведения: структуры и кортежи

```ixion
type Point = struct {
    x: int,
    y: int,
}

const p = Point(2, 3)
const q = p with { x = 10 }
const pair: (int, string) = (1, "one")
```

Все поля обязательны, неизменяемы и инициализируются конструктором в порядке
объявления. Наследования, setter-методов и частично созданных значений нет.
Пустая структура разрешена, конструируется `Name()`.

`value with { field = expression, ... }` создаёт значение **того же** типа структуры,
заменяя перечисленные поля. База вычисляется один раз, затем новые значения
слева направо в исходной области видимости. Пропущенные поля сохраняются;
неизвестные и повторные поля — ошибка. Даже пустое обновление не обязано
создавать отдельный объект. Для вложенного обновления используются вложенные `with`.
Обновление суммы целиком и кортежа через `with` запрещено.

Кортеж — упорядоченное произведение: `(A, B)`, `(A, B, C)`.
`(value)` — группировка, `(value,)` — одноэлементный кортеж, `()` — `unit`.
Компоненты извлекаются шаблоном; числовые свойства вроде `.0` не вводятся.

## 7. Закрытые суммы с данными

```ixion
type Option[T] = enum {
    None,
    Some(value: T),
}

type Result[T, E] = enum {
    Ok(value: T),
    Err(error: E),
}

type Expr = enum {
    Number(value: int),
    Add(left: Expr, right: Expr),
    Multiply(left: Expr, right: Expr),
}

const present: Option[int] = Option::Some(42)
const absent = Option[int]::None
const expression = Expr::Add(Expr::Number(1), Expr::Number(2))
```

`enum` объявляет конечное непустое множество вариантов. Вариант — нуль или более
именованных полей. Имена вариантов уникальны внутри суммы, поля — внутри варианта.
Вариант без полей записывается `None`; форма `None()` в объявлении не допускается.
Значение без данных записывается `Type::Variant`, с данными —
`Type::Variant(args)`. Явная специализация: `Type[T]::Variant(args)`.

Варианты принадлежат одной номинальной сумме; `Result::Ok` и `Option::Some`
не являются самостоятельными типами. Поля варианта доступны только после
деструктуризации через `case`; обращение `result.value` к сумме запрещено.
Отдельное объявление варианта вне тела типа запрещено.

Рекурсивные и взаимно рекурсивные ADT разрешены. Вхождение определяемого типа
в параметры функционального типа под нечётным числом переходов через аргумент
функции (отрицательная позиция) запрещено. Через пользовательский generic-тип
рекурсия допустима только если анализ его полей доказывает положительность
соответствующего параметра; это не изменяет правило инвариантности присваивания.
Рекурсивные aliases без номинального узла запрещены. Отсутствие конечного
значения у типа вроде `Loop = struct { next: Loop }` допустимо; создавать
циклические объекты обходом конструктора нельзя.

`enum` без данных остаётся частным случаем ADT:

```ixion
type Direction = enum { North, South, East, West }
```

## 8. Анонимные объединения и aliases

```ixion
type Number = int | float
const n: Number = 10

const label = case n {
    int value => "integer",
    float value => "float",
}
```

`A | B` — объединение уже существующих типов, а не объявление именованных вариантов.
Вложенные объединения распрямляются; повторные типы и `never` удаляются;
порядок альтернатив не влияет на тождество. `A | any` нормализуется в `any`.
Объединение из одной альтернативы совпадает с ней. Alias раскрывается перед
нормализацией; циклические цепочки aliases — ошибка.

Для включения значения сначала выбирается точное совпадение альтернативы,
затем единственная подходящая по разрешённому расширению. Несколько кандидатов
без точного совпадения требуют явной аннотации/промежуточной привязки нужного типа.
Преобразование `A | B` в `A | B | C` разрешено, если каждая исходная альтернатива
имеет однозначное включение в целевое объединение.

Альтернатива является частью семантики значения: включение `int` в `int | float`
не превращает его во `float`. Runtime обязан различать также `Box[int]` и
`Box[string]`; проверки одного JVM-класса недостаточно. Реализация может хранить
скрытый тег типа или эквивалентную информацию. Типовой шаблон объединения
выбирает объявленную альтернативу, без числовых преобразований.

Для предметных моделей рекомендуется закрытая именованная сумма: она различает
например `UserId(value: int)` и `OrderId(value: int)` внутри одного ADT.

## 9. Сопоставление с образцом

### 9.1. Вычисление и результат

```ixion
def eval(expr: Expr): int {
    return case expr {
        Expr::Number(value) => value,
        Expr::Add(left, right) => eval(left) + eval(right),
        Expr::Multiply(left, right) => eval(left) * eval(right),
    }
}
```

`case` вычисляет scrutinee один раз и проверяет ветви в порядке
исходного текста. Выполняется первая подходящая ветвь с истинным guard.
Ни одно тело другой ветви не вычисляется.

Правая часть — выражение или блок-выражение. Последнее выражение блока без
оператора после него задаёт его значение; пустой блок имеет тип `unit`.
`return expression` внутри ветви выходит из ближайшей функции/лямбды, а не из `case`,
и имеет тип `never` для объединения потоков управления.
`case`, используемый отдельным оператором, тоже обязан быть полным; его результат
отбрасывается. Ветки имеют общий тип по правилам раздела 5.2.

### 9.2. Шаблоны

| Форма | Значение |
| --- | --- |
| `_` | Любое значение без привязки |
| `name` | Любое значение с новой неизменяемой привязкой |
| `42`, `"ok"`, `true`, `()` | Литерал соответствующего типа |
| `Option::Some(p)` | Вариант и шаблон данных |
| `Point { x: px, y: py }` | Структура с шаблонами полей |
| `(p, q)` | Кортеж |
| `[p, q]` | Список ровно из двух элементов |
| `[head, ..tail]` | Непустой список и неизменяемый хвост |
| `int value`, `Box[int] box` | Уточнение альтернативы объединения или `any` |

Шаблоны вкладываются без ограничения фиксированной глубины. В шаблоне
структуры пропущенные поля игнорируются; неизвестное или повторное поле — ошибка.
Вариант должен перечислять все поля по позиции, пропуск задаётся `_`.
`..tail`/`.._` разрешён только последним элементом спискового шаблона.
`[..tail]` сопоставляется с любым списком. Литералы в шаблонах не выполняют
числовых расширений. Отрицательный числовой литерал также допустим.

Каждое имя в одном шаблоне объявляется не более одного раза. Область видимости
привязок — guard и тело этой ветви. Ссылка на существующую константу не является
шаблоном значения: одиночное имя всегда вводит привязку.
Типовой шаблон требует точной альтернативы объединения; для `any` проверяется
семантический тип значения, включая аргументы generic-типа.

### 9.3. Guards, полнота и недостижимость

```ixion
def classify(value: Option[int]): string {
    return case value {
        Option::Some(x) if x > 0 => "positive",
        Option::Some(_) => "non-positive",
        Option::None => "absent",
    }
}
```

Guard имеет тип `bool`, вычисляется после успешного шаблона и до тела.
Ложный guard продолжает поиск со следующей ветви. Guards могут иметь эффекты;
компилятор не вправе менять их порядок или повторять их вычисление.

Проверка полноты учитывает вложенные варианты, произведения, `bool`, `unit`
и формы списков. Для бесконечных/открытых областей (`int`, `string`, `any`,
функции) требуется покрывающий шаблон `_`, привязка или полный типовой шаблон
соответствующей альтернативы. Любая ветвь с guard, даже `if true`, не добавляет
покрытие в этой редакции. Например, `Some(true)` и `None` не покрывают `Option[bool]`.

Неполный `case` — ошибка с примером пропущенного значения/шаблона.
Доказуемо недостижимая ветвь — ошибка: в частности, повторное покрытие после
безусловного wildcard или после исчерпывающего набора предыдущих ветвей.
Guard сам по себе не позволяет доказать покрытие следующих ветвей.
Анализ рекурсивных типов должен завершаться; он не требует полного разворачивания
рекурсии. При лимите ресурсов компилятор сообщает о невозможности доказать
полноту и предлагает добавить покрывающую ветвь, но не принимает неполный `case`.

## 10. Неизменяемые списки

`T[]` — однородный неизменяемый список, включая вложенные списки.
Вызовы функций не могут изменять его через другую ссылку или итератор.
Реализация может разделять неизменяемые узлы; наблюдаемая идентичность памяти
не входит в семантику языка. Первая реализация может копировать данные;
структурное разделение памяти не является условием соответствия.

```ixion
const xs: int[] = [1, 2, 3]
const ys = std::append(xs, 4)
const zs = std::updated(xs, 0, 10)
const first: Option[int] = std::get(xs, 0)
```

Обязательное ядро API `std` (generic-сигнатуры):

```ixion
def len[T](xs: T[]): int
def append[T](xs: T[], value: T): T[]
def concat[T](left: T[], right: T[]): T[]
def get[T](xs: T[], index: int): Option[T]
def updated[T](xs: T[], index: int, value: T): Option[T[]]
def map[A, B](xs: A[], f: (A) => B): B[]
def filter[T](xs: T[], predicate: (T) => bool): T[]
def fold[A, B](xs: A[], initial: B, f: (B, A) => B): B
```

Эти строки задают API, а не объявления без тела в исходном языке.
`get`/`updated` возвращают `None` при отрицательном индексе или выходе за границы.
`xs[index]` — сокращение `std::get(xs, index)` с результатом `Option[T]`.
`map`, `filter`, `fold` вызывают функцию последовательно слева направо ровно
один раз на элемент. `for item : xs { ... }` обходит неизменяемый снимок.

`std::push` и `std::pop` с изменением аргумента удаляются. Старый пустой литерал
`int[]` заменяется на `const xs: int[] = []`. Типы `Map`/`Set`, mutable builders
и гарантии асимптотической сложности относятся к отдельным расширениям.

## 11. Равенство и представление

`==` и `!=` для структур, ADT, кортежей и списков сравнивают значения рекурсивно.
Для ADT требуются одинаковые номинальный тип, аргументы типа, вариант и данные;
для списков — одинаковая длина и попарно равные элементы. Разные номинальные
типы нельзя сравнивать без явного общего типа. При сравнении объединений
сначала сравниваются семантические альтернативы, затем их данные.

Числа сравниваются после допустимого числового расширения. Для `float`/`double`
используется IEEE 754: NaN не равен себе, `-0.0` равен `0.0`. Это же правило
применяется рекурсивно внутри контейнеров. Строки сравниваются по содержимому.

Равенство функций, внешних ресурсов и `any` статически запрещено. Контейнер
с таким компонентом также не поддерживает равенство. Неограниченный `T`
не поддерживает `==`: ограничения/traits равенства будут отдельным расширением.
Хеширование доступно только для типов с равенством; равные значения обязаны
иметь одинаковый хеш, включая случай `-0.0`/`0.0`.

`std::print`/`println` принимают любое значение и используют диагностическое
представление; точное форматирование не является сериализационным контрактом.
Оператора сравнения ссылок или изменения поля через reflection в языке нет.

## 12. Функции, управление и операторы

```ixion
def sum(values: int[]): int {
    var total = 0
    for value : values {
        total += value
    }
    return total
}
```

Параметры функций типизированы и неизменяемы. Функции вызываются `f(args)`;
аргументы вычисляются слева направо. Рекурсия разрешена без обязательной
оптимизации хвостовых вызовов. Обычная функция с результатом не-`unit` должна
явно возвращать значение на каждом нормально достижимом пути.
Последнее выражение блока функции не заменяет `return`.
Проверка потоков выполняется после разрешения типов и полноты `case`, не парсером.

`if condition { ... } else { ... }`, `while condition { ... }` и
`for item : iterable { ... }` остаются операторами. Условия имеют строго тип `bool`.
Пропущенный `else` разрешён; цикла без гарантированного возврата недостаточно
для выполнения обязательства `return`. `for` поддерживает списки и строки;
для строки элемент — `char` в порядке UTF-16. `start..stop` задаёт диапазон `int`
с включённым началом и исключённым концом; при `start >= stop` диапазон пуст.
`break` и `continue` в эту редакцию не вводятся.

Приоритеты выражений от низшего к высшему:

| Уровень | Операции | Ассоциативность |
| --- | --- | --- |
| 1 | `with { ... }` | левая |
| 2 | `^` (булево XOR) | левая |
| 3 | `||` | левая |
| 4 | `&&` | левая |
| 5 | `== != < <= > >= ..` | без цепочек |
| 6 | `+ -` | левая |
| 7 | `* / %` | левая |
| 8 | `**` | правая |
| 9 | префиксные `+ - !` | правая |
| 10 | вызов, индексация, `.field`, специализация | левая |

`&&` и `||` вычисляются коротко, `^` вычисляет оба булевых аргумента.
`%` — только бинарный остаток, префиксная форма удалена.
`+` поддерживает числа и конкатенацию двух строк; автоматическая конкатенация
строки с произвольным значением не требуется. `< <= > >=` — числовые сравнения.
Целочисленная арифметика использует переполнение JVM `int`; целочисленные
деление/остаток на ноль аварийны. `int ** int` при неотрицательной степени
возвращает `int` с тем же переполнением, отрицательная степень аварийна.
Для вещественной степени действует IEEE 754 с общим числовым типом.

## 13. Ошибки, стандартные ADT и внешняя граница

`Option` и `Result` из раздела 7 предопределены и не требуют `use`;
это обычные ADT с обычными конструкторами и правилами `case`.
В модуле нельзя повторно объявлять эти имена. Прикладные функции используют
`Result` для ожидаемых ошибок. `std::panic(message: string): never`
завершает вычисление аварийно и не подменяет `Result`.

JVM-объект с изменяемым состоянием — внешний ресурс, а не неизменяемые данные
Ixion. Импортируемые операции обязаны иметь явные Ixion-сигнатуры.
Внешние ресурсы можно держать в локальных привязках и передавать внешним
операциям, но нельзя помещать в структуры, ADT, кортежи, списки или модульные
константы. Запрет применяется транзитивно после подстановки аргументов типа;
упаковка в `any` или замыкание, захватившее ресурс, его не снимает.

Адаптер внешнего API преобразует nullable-результат в `Option[T]`, копирует
изменяемую коллекцию в Ixion-список и не выдаёт наружу изменяемое хранилище.
Неизвестные generic-параметры Java не превращаются автоматически в `any`.
Передача Ixion-данных наружу требует адаптера, сохраняющего их неизменяемость
(копии либо безопасного read-only представления). HTTP и async остаются
эффектными модулями; неизменяемость данных сама по себе не обещает отсутствие
гонок во внешних ресурсах.

## 14. Грамматика нового ядра

EBNF ниже фиксирует объявления, типы, шаблоны и новые формы выражений.
`expression` использует таблицу приоритетов раздела 12 и первичные формы ниже;
это грамматика ядра, а не полный листинг арифметических productions.
`ident` исключает ключевые слова и одиночный `_`, `literal` включает `()`.
В правилах последовательностей завершающая запятая допустима только после элемента.

```ebnf
program         = { use_decl | [ "pub" ] (type_decl | function_decl | const_decl) } ;
use_decl        = "use" "<" ident { "/" ident } ">" ;
type_decl       = "type" ident [ type_params ] "=" (struct_def | enum_def | type_expr) ;
type_params     = "[" ident { "," ident } [ "," ] "]" ;
struct_def      = "struct" "{" [ fields ] "}" ;
fields          = field { "," field } [ "," ] ;
field           = ident ":" type_expr ;
enum_def        = "enum" "{" variant { "," variant } [ "," ] "}" ;
variant         = ident [ "(" fields ")" ] ;
function_decl   = "def" ident [ type_params ] "(" [ fields ] ")"
                  [ ":" type_expr ] block ;
const_decl      = "const" ident [ ":" type_expr ] "=" expression ;
var_decl        = "var" ident [ ":" type_expr ] "=" expression ;
qualified       = ident { "::" ident } ;
type_expr       = function_type | union_type ;
function_type   = "(" [ type_items ] ")" "=>" type_expr ;
union_type      = postfix_type { "|" postfix_type } ;
postfix_type    = type_atom { "[" "]" } ;
type_atom       = qualified [ type_args ] | "never"
                | "(" ")" | "(" type_expr ")" | tuple_type ;
type_args       = "[" type_items "]" ;
type_items      = type_expr { "," type_expr } [ "," ] ;
tuple_type      = "(" type_expr "," [ type_items ] ")" ;

case_expr       = "case" expression "{" [ branches ] "}" ;
branches        = branch { "," branch } [ "," ] ;
branch          = pattern [ "if" expression ] "=>" (block_expr | expression) ;
pattern         = "_" | literal | negative_number | ident
                | qualified [ type_args ] "::" ident [ "(" patterns ")" ]
                | qualified [ type_args ] "{" [ field_patterns ] "}"
                | "(" pattern ")" | tuple_pattern | list_pattern
                | type_expr ident ;
patterns        = pattern { "," pattern } [ "," ] ;
field_patterns  = field_pattern { "," field_pattern } [ "," ] ;
field_pattern   = ident ":" pattern ;
tuple_pattern   = "(" pattern "," [ patterns ] ")" ;
list_pattern    = "[" [ patterns_no_trailing [ "," rest_pattern ]
                          | rest_pattern ] [ "," ] "]" ;
patterns_no_trailing = pattern { "," pattern } ;
rest_pattern    = ".." (ident | "_") ;

update_suffix   = "with" "{" [ updates ] "}" ;
updates         = update { "," update } [ "," ] ;
update          = ident "=" expression ;
assignment_stmt = ident ("=" | "+=" | "-=" | "*=" | "/=" | "%=") expression
                | ident ("++" | "--") ;
return_stmt     = "return" expression ;
block           = "{" { statement } "}" ;
block_expr      = "{" { statement } [ expression ] "}" ;
```

Прочие первичные формы: литерал, квалифицированное имя, конструктор варианта,
группировка, кортеж, список, лямбда, `case`.
Специализация в выражении `name[T]` разбирается как аргументы типа только для
имени функции/конструктора/типа; индексация значения `xs[index]` остаётся индексацией.
При совпадении имён приоритет определяется пространством имён и последующим
вызовом либо `::Variant`; неоднозначная форма требует другого имени или группировки.
В частности, `(xs)[index]` всегда индексирует значение.

`statement` включает локальные объявления, присваивания, `return`, `if`,
`while`, `for`, блок и выражение. В `block_expr` последнее выражение трактуется
как результат, остальные выражения — как операторы с отброшенным значением.
Пустой `case value {}` разрешён только для scrutinee типа `never` и сам имеет
тип `never`; для всех остальных типов требуется хотя бы одна ветвь.

## 15. Обязательные диагностические категории

Компилятор должен отклонять до кодогенерации:

- переприсваивание `const`, параметра или привязки шаблона;
- запись в поле/индекс, в том числе через `var` или `any`;
- ошибочную арность типа, конструктора или шаблона;
- неизвестный вариант/поле и повторную привязку в шаблоне;
- несовместимые ветви и неразрешённые параметры типа;
- неполный `case` с примером пропущенного шаблона;
- доказуемо недостижимую ветвь;
- неподтверждённый возврат, рекурсивный alias и отрицательную рекурсию;
- попадание внешнего изменяемого ресурса в неизменяемые данные.

Сообщение содержит исходный диапазон и ожидаемый/фактический тип, если применимо.
Внутренняя ошибка бэкенда не заменяет пользовательскую диагностику.

## 16. Совместимость и границы редакции

| Сейчас / прежняя спецификация | Целевая форма |
| --- | --- |
| `var` как обычное объявление | `const`; `var` только для локального переприсваивания |
| `type Box = struct [T] { ... }` | `type Box[T] = struct { ... }` |
| `enum` из имён | Тот же `enum`, расширенный вариантами с данными |
| `case x { int n => ... }` как оператор | Сохраняемый типовой шаблон внутри `case`-выражения, ветви через запятую |
| Изменяемые списки, `push`/`pop` | Неизменяемые списки и функции, возвращающие новые значения |
| `int[]` как пустое значение | `const xs: int[] = []` |
| `xs[i]` возвращает элемент | `xs[i]` возвращает `Option[T]` |
| `void`, пустой `return` | Alias `unit`, `return ()` |
| Квалификация типа через `.` | `module::Type`; `.` остаётся доступом к полю |
| Равенство объектов зависит от JVM-представления | Структурное равенство данных с правилами раздела 11 |

Переход намеренно несовместим; смешивать старую и новую семантику списков
в одном режиме компиляции запрещено. Старые README, руководства и примеры
до миграции описывают текущую реализацию, а не этот проект.

Не входят в эту редакцию: GADT и уточнение параметров типа по варианту,
экзистенциальные и зависимые типы, higher-kinded types, type classes/traits,
row polymorphism, открытые суммы, пользовательская вариантность, operator overloading,
автоматический `?` для `Result`, OR/as-шаблоны и система эффектов.
Эти расширения не должны требоваться для реализации параметрических,
рекурсивных ADT и полного вложенного сопоставления из настоящего документа.
